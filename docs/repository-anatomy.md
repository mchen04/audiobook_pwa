# Repository anatomy

Last reviewed: 2026-07-28

This note explains why a raw line count approaches 100,000 and which large
paths are authored code, required generated state, or disposable local output.

## Tracked-line breakdown

The July 2026 audit counted 93,675 lines across tracked text files:

| Path or file                | Approximate lines | Classification                                              |
| --------------------------- | ----------------: | ----------------------------------------------------------- |
| `drizzle/`                  |            36,639 | required SQL history and generated snapshots                |
| `src/`                      |            31,038 | application plus co-located unit tests                      |
| `tests/`                    |            15,937 | browser, parity, sync, resume, and performance verification |
| `pnpm-lock.yaml`            |             8,316 | required generated dependency state                         |
| `docs/`                     |             1,133 | maintained product and operations docs                      |
| `scripts/`, `public/`, root |             1,612 | tooling, authored worker, and config                        |

The number is therefore not 94k lines of production application logic.
Generated migration/dependency state accounts for about 45k lines, and test
infrastructure accounts for much of the remainder.

## Generated but required

`drizzle/meta/*.json` is not disposable build output. Drizzle Kit reads the
snapshot chain, validates parent/version relationships, and compares the
current schema with the latest migration state when generating the next SQL
migration. Removing old snapshots breaks that history. Drizzle's own
[`generate` documentation](https://orm.drizzle.team/docs/drizzle-kit-generate)
describes the SQL-plus-snapshot output.

`pnpm-lock.yaml` pins exact dependency resolution and is required for
reproducible frozen installs.

Both paths are marked `linguist-generated` in `.gitattributes`. GitHub documents
that attribute as the way to collapse generated files in diffs and remove them
from repository language statistics:
<https://docs.github.com/en/repositories/working-with-files/managing-files/customizing-how-changed-files-appear-on-github>.

## Large authored files

These files are large, but they are referenced and behavior-bearing:

- `tests/resume/harness/resume-oracle.ts` (~5k lines) is the shared
  cross-process/device resume oracle used by three Playwright suites. It is not
  bundled into production. Its size is maintainability debt and a candidate for
  decomposition, not evidence that it should be deleted.
- `src/lib/offline/idb-migrate.test.ts` (~1.4k lines) carries every shipped
  IndexedDB schema forward and proves that downloads, transcripts, queued
  writes, and deletion state survive.
- `src/app/styles/player.css` (~1.3k lines) is authored player UI, not compiled
  CSS.
- `tests/perf/launch-benchmark.spec.ts` and `src/lib/offline-sync.ts` are each
  just over 1.1k lines and own the launch oracle and legacy sync boundary,
  respectively.
- `public/sw.js` is maintained directly and is the shipping service worker; it
  is not generated by the build.

This audit does not disguise authored files as generated to improve statistics.
Future structural work should split a large file only along real ownership
boundaries and preserve each oracle's ability to fail.

## Disposable local output

The following remain ignored and should never be committed:

- `.next/`, `out/`, `tsconfig.tsbuildinfo`, and `next-env.d.ts`;
- `node_modules/`;
- `test-results/`, `playwright-report/`, and `coverage/`;
- `.data/`, uploads, local mail captures, and imported MP3s;
- `.env*` except the checked-in examples;
- `.vercel/`, editor state, and agent scratch directories.

Test MP3s under `tests/fixtures/` are exceptions: tests reference these small
files directly. `public/icon-source.svg` is the retained source asset for the
generated PNG icons.

## Counting consistently

For repository size, count tracked files rather than the working directory:

```sh
git ls-files
```

A working-directory count includes dependencies and compiled Next.js output and
can be hundreds of megabytes larger. GitHub's language panel is byte-based and
honors `.gitattributes`; it is not the same metric as source lines.
